# SvelteKit Reactive State Binding and Ephemeral API Secret Key Flow

## Context
The API Key management UI in `apps/dashboard-web` (`[orgSlug]/settings/keys` and `[orgSlug]/projects/[projectId]/settings/keys`) previously used static mock arrays and client-side placeholders. Connecting these pages to the PostgreSQL-backed API endpoints (`/api/organizations/[orgId]/keys`, `.../rotate`, and `.../revoke`) required:
1. Hydrating server-side data from `+page.server.ts` loaders.
2. Maintaining reactive synchronization between Svelte page data and client-side mutation updates.
3. Ensuring security compliance for single-exposure secret tokens (`sent_org_...` and `sk_proj_...`) without storing unhashed secrets in local UI state.

## Guidance

### 1. Svelte Reactive Re-binding for Server Data
When initializing page components with server data passed via `export let data`, static `let keys = data.keys` declarations disconnect local state from SvelteKit page load re-evaluations. Use reactive declarations (`$:`) to maintain synchronization across page parameter navigation while preserving immediate client-side mutation feedback.

```svelte
<script lang="ts">
	export let data: {
		orgId: string;
		orgSlug: string;
		keys: any[];
		projects: Array<{ id: string; name: string }>;
	};

	// Reactive assignment ensures data updates on navigation re-runs
	$: keys = data.keys || [];
	$: projects = data.projects || [];
</script>
```

### 2. Single-Exposure Ephemeral Secret Banner
Secret API keys generated by backend mutations (`POST /api/organizations/[orgId]/keys` or `.../rotate`) are returned unhashed exactly once in the HTTP response payload (`{ key: apiKey, token: secretToken }`).

- Render the secret token in an ephemeral top-of-page alert tray (`newlyCreatedToken`).
- Never persist unhashed secret tokens to `localStorage`, `sessionStorage`, or local client arrays.
- Provide a 1-click clipboard action with auto-reset feedback.

```svelte
{#if newlyCreatedToken}
	<div class="bg-amber-950/60 border-2 border-amber-500/80 rounded-xl p-5">
		<div class="flex items-center gap-3">
			<div class="flex-1 font-mono text-sm text-emerald-400 select-all">
				{newlyCreatedToken}
			</div>
			<button on:click={() => copyToClipboard(newlyCreatedToken)}>
				{copiedToken ? '✓ Copied' : 'Copy Secret'}
			</button>
		</div>
	</div>
{/if}
```

### 3. Server Loader Endpoint Proxying
Keep page server loaders (`+page.server.ts`) lean by resolving route entities (e.g. `orgSlug` to `orgId`) and calling existing REST API endpoints via SvelteKit's event `fetch`.

```typescript
import { error } from '@sveltejs/kit';
import type { PageServerLoad } from './$types';
import { db } from '$lib/server/db';
import { organizations } from '$lib/db/schema';
import { eq } from 'drizzle-orm';

export const load: PageServerLoad = async ({ params, fetch }) => {
	const { orgSlug } = params;

	const [org] = await db
		.select({ id: organizations.id })
		.from(organizations)
		.where(eq(organizations.slug, orgSlug));

	if (!org) throw error(404, 'Organization not found');

	const res = await fetch(`/api/organizations/${org.id}/keys`);
	if (!res.ok) throw error(res.status, 'Failed to fetch API keys');

	const { keys } = await res.json();
	return { orgId: org.id, keys: keys || [] };
};
```

## Why This Matters
- Prevents stale UI states during soft route switches between different organizations or projects.
- Eliminates security risks associated with storing raw API secrets in persistent client state.
- Preserves clean architectural boundaries by reusing verified REST endpoints (`/api/organizations/[orgId]/keys`) rather than duplicating backend query logic inside SvelteKit loaders.

## When to Apply
- When implementing secret management UIs (API keys, webhooks, access tokens).
- When integrating SvelteKit `+page.server.ts` loaders with REST API routes.
